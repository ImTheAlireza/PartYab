> من در مخزن کد فایل و پکیج آماده می‌سازم؛ آپلود آخر با توست. این هم امن‌تر است و هم مالکیت کامل روی سایت دست خودت می‌ماند. **هیچ‌جا رمز هاست یا FTP را نفرست.**

## ۱. سه روش تحویل — از بهترین به ساده‌ترین

| # | روش | مناسب برای | چطور |
|---|---|---|---|
| ۱ | **Git روی هاست** (اگر پنل پشتیبانی کند) | آپدیت‌های بعدی | یک‌بار ریپو را clone کن، بعد از هر تغییر `git pull` |
| ۲ | **آپلود ZIP از پیشخوان** | چایلد تم و پلاگین‌ها | فایل ZIP را با اسکریپت `tools/package-theme.sh` بساز و در «نمایش ← پوسته‌ها ← افزودن» آپلود کن |
| ۳ | **FTP / File Manager** | فایل‌های تک | فقط وقتی روش ۱ و ۲ نیست |

اسکریپت بسته‌بندی:

```bash
bash tools/package-theme.sh        # خروجی: dist/part-yab.zip
```

## ۲. چه چیزی از تو لازم است (فقط ۴ جواب، نه رمز)

1. پنل هاست چیست؟ (cPanel / DirectAdmin / پنل اختصاصی / نمي‌دانم)
2. نسخه PHP روی هاست چه عددی است؟ (هدف: ۸٫۳)
3. هاست امکان **ساخت محیط Staging** دارد؟ (بله / نه)
4. دامنه نهایی روی همین هاست است یا جدا؟ (برای گواهی SSL و تنظیم محیط)

با همین چهار جواب، مراحل ۳ تا ۶ را دقیق و مخصوص پنل خودت می‌نویسم.

## ۳. ساخت سه محیط

| محیط | دستور کار |
|---|---|
| **Local** | Local by Flywheel یا XAMPP · PHP 8.3 · `WP_DEBUG=true` · نصب افزونه‌های سبد |
| **Staging** | کپی از Production + `noindex` + `WP_DEBUG=false` + رمز Basic Auth روی کل سایت |
| **Production** | فقط انتشار تأییدشده · کش فعال · بک‌آپ روزانه |

**قاعده انتشار یک‌طرفه:** Local → Staging → Production. هیچ‌وقت مستقیم روی Production ویرایش نکن.

ساخت Staging اگر پنل ندارد (روش دستی، یک‌بار):
1. از Production بک‌آپ کامل بگیر (فایل + دیتابیس).
2. روی زیردامنه `staging.example.com` نصب کن و دیتابیس را ایمپورت کن.
3. با [Better Search Replace] آدرس‌های قدیم را به زیردامنه تغییر بده.
4. `Settings → Reading → Search engine visibility` را تیک بزن.

## ۴. کارهای بعد از هر آپلود (چک‌لیست ۶ مرحله‌ای)

1. پاک‌کردن کش: LiteSpeed Cache → Purge All + کش مرورگر (Ctrl+Shift+R).
2. `تنظیمات ← پیوندهای یکتا` را یک‌بار Save کن (رفع ۴۰۴ بعد از تغییر ساختار).
3. تست سه صفحه: خانه، یک محصول، سبد.
4. کنسول مرورگر: نباید خطای JS داشته باشد.
5. تست موبایل واقعی (نه فقط حالت ریسپانسیو).
6. اگر خطای کشف‌نشده بود، طبق بخش ۵ برگرد عقب.

## ۵. برگشت عقب (Rollback)

| چه چیزی خراب شد | برگشت |
|---|---|
| فقط قالب | آپلود ZIP نسخه قبلی (از `dist/` نگه‌دار) یا `git checkout <tag>` |
| افزونه | غیرفعال کردن از پیشخوان؛ اگر صفحه سفید شد، پوشه افزونه را با FTP تغییر نام بده |
| دیتابیس | ایمپورت بک‌آپ UpdraftPlus از پیشخوان (قبل از هر تغییر ساختاری بک‌آپ دستی بگیر) |

**قاعده طلایی:** قبل از هر تغییر ساختاری (جدول، تاکسونومی، مهاجرت داده) یک بک‌آپ دستی با نام تاریخ‌دار بگیر.
