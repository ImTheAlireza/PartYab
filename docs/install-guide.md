# راهنمای نصب بی‌خطر پارت‌یاب (قالب + افزونه)

هدف این سند: نصب بدون این‌که سایت فعلی یا فروشگاه در حال کار آسیب ببیند.
خلاصهٔ یک‌خطی: **اول بکاپ، بعد روی نسخهٔ آزمایشی (staging) نصب و تست، بعد روی سایت اصلی.**

---

## ۱. نیازمندی‌ها

### حداقل و پیشنهادی

| مورد | حداقل | پیشنهاد ما | چرا |
|---|---|---|---|
| وردپرس | ۶.۲ | ۶.۶ یا بالاتر | تست‌شده تا ۶.۷ |
| PHP | ۷.۴ | **۸.۱ یا ۸.۲** | سرعت و پشتیبانی؛ کد با ۷.۴ سازگار نوشته شده |
| ووکامرس | ۷.۰ | ۹.۰ یا بالاتر | تست‌شده تا ۹.۴؛ بدون ووکامرس بخش فروشگاه کار نمی‌کند |
| دیتابیس | MySQL 5.7 / MariaDB 10.4 | — | جدول اختصاصی سازگاری ساخته می‌شود |
| افزونهٔ PHP | `mbstring`، `json`، `mysqli` | همان | کاتالوگ خودرو برای نرمال‌سازی متن فارسی از `mbstring` استفاده می‌کند |
| حافظهٔ PHP | ۱۲۸ مگابایت | ۲۵۶ مگابایت | ایمپورت CSV و صفحهٔ محصول |
| `max_execution_time` | ۳۰ ثانیه | ۶۰ ثانیه | ایمپورت فایل بزرگ سازگاری |
| `upload_max_filesize` | ۲ مگابایت | ۸ مگابایت | زیپ قالب ۱٫۱ مگابایت است |
| پیوند یکتا | «نام نوشته» | — | REST API (`/wp-json/partyab/v1/`) بدون آن کار نمی‌کند |
| دسترسی | ادمین وردپرس | — | نصب پوسته/افزونه و ایمپورت داده |
| هم‌زمانی | HTTPS | HTTPS | مسیر حساب کاربری و درگاه پرداخت |

### چیزهایی که **لازم نیست**
- Node.js، npm، Composer، بیلد استپ — هیچ‌کدام.
- دسترسی به اینترنت برای سایت: فونت‌ها، تصاویر و ۴۸ آیکون همه محلی و درون‌خطی هستند؛ هیچ درخواستی به CDN/Google Fonts زده نمی‌شود.
- SSL اجباری برای دیدن قالب، ولی برای کوکی خودرو و حساب کاربری توصیهٔ جدی است.

### سازگاری‌های اعلام‌شده
- **HPOS** (جدول سفارش‌های ووکامرس): افزونه رسماً `custom_order_tables` را declare کرده؛ با هر دو حالت کار می‌کند.
- **مالتی‌سایت:** تست نشده. اگر شبکه‌ای دارید، اول روی یک زیرسایت آزمایشی نصب کنید.
- **صفحه‌سازها (Elementor/Divi):** قالب مستقل است؛ اگر برگه‌ها را با صفحه‌ساز می‌سازید، استایل‌ها فقط روی پوسته‌های خود قالب تضمین می‌شوند.

> ⚠️ صداقت فنی: کد PHP در محیط توسعه فقط «سینتکس‌چک» شده و روی یک نصب واقعی وردپرس اجرا نشده. اولین نصب واقعی باید روی staging باشد — این سند دقیقاً برای همین نوشته شده.

## ۲. چک‌لیست ۵ دقیقه‌ای قبل از شروع

1. **بکاپ کامل**: فایل‌ها (`wp-content` دست‌کم) + دیتابیس. با UpdraftPlus یا از پنل هاست.
2. **نسخه‌ها**: وردپرس، PHP و ووکامرس را در «پیشخوان → ابزارها → سلامت سایت → اطلاعات» ببین.
3. **پوستهٔ پیش‌فرض موجود باشد** (مثلاً Twenty Twenty-Four). این «کپسول نجات» شماست.
4. **حالت تعمیر/ساعت کم‌ترافیک**: نصب را در ساعتی انجام بده که سفارش کم است.
5. **افزونهٔ کش را بشناس**: کش صفحه، کش مرورگر، CDN و آبجکت‌کش (Redis). بخش ۷ را قبل از فعال‌سازی بخوان.
6. **زیپ‌ها را باز نکن**: فایل `dist/partyab.zip` و `dist/partyab-fitment.zip` را همان‌طور که هستند آپلود کن.

## ۳. سه روش نصب (بی‌خطرترین اول)

### روش الف — از پیشخوان با زیپ (توصیه‌شده، بدون دسترسی FTP)

۱. **نمایش → پوسته‌ها → افزودن پوسته → بارگذاری پوسته** → `dist/partyab.zip` → «اکنون نصب کن».
۲. **افزونه‌ها → افزودن افزونه → بارگذاری افزونه** → `dist/partyab-fitment.zip` → «اکنون نصب کن».
۳. هر دو با هم **فعال** کن.

اگر پیام `The link you followed has expired` یا محدودیت آپلود گرفتی: `upload_max_filesize`/`post_max_size` را بالا ببر یا از روش ب استفاده کن.

### روش ب — با FTP/SFTP (سازگارترین)

```bash
# روی کامپیوتر خودت زیپ را باز کن
unzip dist/partyab.zip            # پوشهٔ partyab
unzip dist/partyab-fitment.zip     # پوشهٔ partyab-fitment

# آپلود در:
wp-content/themes/partyab/
wp-content/plugins/partyab-fitment/
```

بعد از آپلود، از پیشخوان فعال‌شان کن. مجوز پوشه‌ها: دایرکتوری `755`، فایل `644`.

### روش ج — WP-CLI (برای کسانی که SSH دارند)

```bash
wp theme install /path/to/dist/partyab.zip --activate
wp plugin install /path/to/dist/partyab-fitment.zip --activate
wp rewrite structure '/%postname%/' && wp rewrite flush
wp plugin list --status=active
```

### ⛔ روش نادرست
- باز کردن زیپ و کپی «فایل‌های داخل پوشه» به‌جای خود پوشه (باید مسیر `themes/partyab/style.css` باشد، نه `themes/style.css`).
- ریختن پوشهٔ `plugin` یا `theme` مخزن گیت (با `.git`) داخل `wp-content`.

## ۳٫۵ نصب خودکار (کوتاه‌ترین و بی‌خطرترین مسیر)

اگر SSH یا WP-CLI داری، به‌جای گام‌های دستی بخش ۵:

```bash
bash bin/install.sh --path=/var/www/html
```

اسکریپت خودش: ووکامرس را (اگر نبود) نصب می‌کند، قالب و افزونه را از `dist/` نصب و فعال می‌کند
و سپس `wp eval-file bin/install.php` را اجرا می‌کند که همان منطق صفحهٔ «ابزارها → نصب سریع پارت‌یاب» است.

| پرچم | کار |
|---|---|
| `--currency=IRR` | واحد پول (پیش‌فرض ریال؛ `IRT` فقط با افزونهٔ تومان) |
| `--no-images` | تصاویر دمو وارد کتابخانهٔ رسانه نشوند |
| `--force` | محصولات موجود با همان SKU به‌روزرسانی شوند (روی سایت واقعی نزن) |
| `--install-woo` | اگر ووکامرس نبود، نصب شود (فقط در WP-CLI) |

بدون SSH: قالب و افزونه را آپلود کن، بعد **ابزارها → نصب سریع پارت‌یاب** را بزن و گزارش را بخوان.
هر ردیف «هشدار» یک کار باقی‌مانده است (مثلاً استثنا کردن کش صفحه)؛ ردیف «خطا» یعنی پیش‌نیازی کم است.

> نصب خودکار، جای چک‌لیست بخش ۹ را نمی‌گیرد. بعد از اجرا، همان ۱۵ مورد را در پنجرهٔ ناشناس تست کن.

## ۴. مسیر طلایی: staging → تست → سایت اصلی

| گام | چه‌کار | چقدر طول می‌کشد |
|---|---|---|
| ۱ | ساخت نسخهٔ آزمایشی (کلون سایت یا نصب تازه) | ۱۰ دقیقه |
| ۲ | نصب قالب و افزونه + ایمپورت داده | ۱۵ دقیقه |
| ۳ | اجرای چک‌لیست تست (بخش ۹) | ۲۰ دقیقه |
| ۴ | اگر همه‌چیز سالم بود، قبل از رفتن روی سایت اصلی دوباره بکاپ بگیر | ۲ دقیقه |
| ۵ | نصب روی سایت اصلی + تست دوبارهٔ ۵ مورد اصلی | ۱۵ دقیقه |

**سه راه برای staging:**
- **هاست:** بیشتر هاست‌های ایرانی/خارجی دکمهٔ «Staging/Clone» در cPanel/DirectAdmin دارند.
- **افزونه:** WP Staging (رایگان) — یک کلون جدا می‌سازد.
- **لوکال:** با LocalWP یا `wp-env` روی کامپیوتر خودت؛ سریع‌ترین راه برای دیدن قالب.

اگر سایت اصلی «در حال فروش» است و staging ندارید: حداقل نصب را در ساعت کم‌ترافیک انجام بده و پوستهٔ قبلی را فعال نگاه دار تا لحظهٔ آخر.

## ۵. گام‌به‌گام نصب (با تأیید بعد از هر گام)

> ترتیب مهم است: **ووکامرس → قالب → افزونه → پیوند یکتا → محصولات → سازگاری → صفحه‌ها → منوها**.

| # | کار | بعد از این گام چه چیزی را ببین |
|---|---|---|
| ۱ | ووکامرس نصب و فعال | صفحه‌های فروشگاه/سبد/تسویه/حساب ساخته می‌شوند |
| ۲ | فعال‌سازی قالب `partyab` | سایت باید بالا بیاید، فارسی، سرمه‌ای/کهربایی، بدون خطای PHP |
| ۳ | تنظیمات → پیوندهای یکتا → «نام نوشته» → ذخیره | آدرس‌ها به شکل `/product/...` درمی‌آیند |
| ۴ | فعال‌سازی افزونهٔ `partyab-fitment` | پیام فعال‌سازی + ساخت جدول `wp_partyab_fitment` در دیتابیس |
| ۵ | افزودن محصولات (بخش ۶) | ۱۳ محصول در «محصولات» |
| ۶ | ایمپورت سازگاری (بخش ۶) | پیام «۳۶ ردیف برای N محصول ذخیره شد» |
| ۷ | ساخت برگهٔ «گاراژ» با الگوی «گاراژ پارت‌یاب» | صفحهٔ گاراژ با کارت‌های خالی و دکمهٔ ثبت خودرو |
| ۸ | تنظیمات → خواندن → صفحهٔ اصلی: یک برگهٔ خالی | صفحهٔ اصلی = `front-page.php` با هیرو و نقشهٔ خودرو |
| ۹ | نمایش → فهرست‌ها: منوی اصلی + دو منوی فوتر | هدر و فوتر پر می‌شوند (بدون منو، لینک‌های پیش‌فرض نمایش داده می‌شود) |
| ۱۰ | نمایش → ابزارک‌ها (فوتر ستون ۱ و ۲، اختیاری) | ستون‌های فوتر سفارشی |

**بعد از هر گام، سایت را در یک پنجرهٔ ناشناس (Incognito) باز کن** تا کش مرورگر گمراهت نکند.

## ۶. ترتیب درست ایمپورت دادهٔ نمونه (خیلی مهم)

⚠️ **اول محصولات، بعد سازگاری.** ایمپورتر سازگاری هر ردیف را با **SKU** به محصول وصل می‌کند؛ اگر محصول وجود نداشته باشد ردیف «SKU ناشناس» می‌شود و رد می‌شود.

۱. **محصولات → همهٔ محصولات → درون‌ریزی** → `plugin/partyab-fitment/sample/products.csv`
   - ستون‌های `Meta: _partyab_oem`، `Meta: _partyab_brand`، `Meta: _partyab_equivalents`، `Meta: _partyab_universal` را دست نزن؛ همین‌ها کد فنی و کدهای معادل را می‌سازند.
   - ستون `Images` عمداً خالی است؛ اگر تصویر می‌خواهی، `theme/partyab/assets/img/p-*.jpg` را از «رسانه → افزودن» آپلود کن و به محصول وصل کن.
۲. **ابزارها → سازگاری پارت‌یاب** → فایل `sample/fitment.csv` → «ایمپورت»
   - ستون‌ها: `sku, make_id, model_id, year_from, year_to, status, note`
   - `status` فقط `fit` یا `conditional`.
   - ردیف‌های هر SKU **جایگزین** ردیف‌های قبلی همان محصول می‌شوند (ایمپورت دوباره چیزی را دوبل نمی‌کند).
۳. **اکسپورت**: همان صفحه دکمهٔ «دریافت CSV» دارد — قبل از هر تغییر بزرگ، از دادهٔ فعلی اکسپورت بگیر.

**شناسهٔ مدل‌ها** از `plugin/partyab-fitment/data/vehicles.json` می‌آید (مثل `m-206`، `m-pride`). اگر مدل تازه می‌خواهی، اول آن فایل را ویرایش کن، بعد CSV را با همان شناسه بساز.

## ۷. ⚠️ دو خطری که واقعاً می‌تواند «به‌هم بریزد»

### خطر ۱ — کش صفحه، خودروی کاربران را قاطی می‌کند
وضعیت سازگاری روی سرور از کوکی `partyab_vehicle` خوانده می‌شود. اگر کش صفحه (LiteSpeed Cache، WP Rocket، Cloudflare APO، W3TC…) صفحهٔ فروشگاه/محصول را برای «همه» کش کند، کاربر A ممکن است وضعیت خودروی کاربر B را ببیند.

**راه‌حل (یکی را انتخاب کن):**
- صفحه‌های `/shop/`، `/product-category/*`، `/product/*` و صفحهٔ گاراژ را از کش **استثنا** کن؛
- یا در کش، کوکی `partyab_vehicle` را جزو `Vary`/متغیرهای کش بگذار (بیشتر کش‌ها گزینهٔ «Vary by cookie» دارند)؛
- یا اصل ساده‌تر: تا وقتی تست تمام نشده، کش صفحه را **خاموش** نگه دار و بعد با استثنا کردن مسیرهای بالا روشن کن.

کش آبجکت (Redis/Memcached) مشکلی ندارد. مینیفای/ترکیب JS هم باید `partyab.js` را دست‌نخورده بگذارد (اسکریپت سادهٔ ES5 است، ولی «Defer/Defer all JS» بعضی افزونه‌ها ترتیب `wc-add-to-cart` را به‌هم می‌زند).

### خطر ۲ — سبد و تسویهٔ «بلوکی» ووکامرس
ووکامرس نسخهٔ ۸.۳+ برای نصب‌های جدید، صفحهٔ سبد و تسویه را با **بلوک** می‌سازد؛ CSS قالب برای نسخهٔ کلاسیک نوشته شده.
اگر ظاهر سبد/تسویه ویجت‌مانند و بی‌استایل دیدی: محتوای دو برگهٔ «سبد خرید» و «تسویه حساب» را با این شورت‌کدها جایگزین کن:

```
[woocommerce_cart]
[woocommerce_checkout]
```

سپس در «ووکامرس → تنظیمات → پیشرفته» مطمئن شو همین دو صفحه انتخاب شده‌اند. صفحهٔ «حساب کاربری» به‌صورت پیش‌فرض شورت‌کد کلاسیک است و مشکلی ندارد.

### دو نکتهٔ کوچک‌تر
- **کوکی و حریم خصوصی:** کوکی `partyab_vehicle` (۱۸۰ روز، `SameSite=Lax`) انتخاب خودرو را نگه می‌دارد و کوکی `partyab_garage` فهرست خودروهای گاراژ را (سمت مرورگر). هر دو «ضروری/کارکردی» هستند؛ در متن سیاست حریم خصوصی به آن‌ها اشاره کن. با پاک‌کردن کوکی‌های مرورگر، گاراژ پاک می‌شود — حساب کاربریِ سروری برای گاراژ وجود ندارد.
- **حذف افزونه = حذف دادهٔ سازگاری.** فایل `uninstall.php` جدول `partyab_fitment` را drop می‌کند (فقط وقتی از پیشخوان «حذف» را بزنی، نه با غیرفعال‌سازی). **قبلش اکسپورت CSV بگیر.**

## ۸. تنظیمات ووکامرس که بعد از نصب چک کن

- **واحد پول:** تومان (یا ریال)، موقعیت نماد سمت راست، جداکنندهٔ هزارگان.
- **کشور فروش:** ایران، استان/شهرهای ایران (برای ارسال و مالیات).
- **روش‌های ارسال:** پیک، پست، تحویل حضوری — هر سه در طراحی دیده شده‌اند.
- **روش‌های پرداخت:** درگاه ایرانی + «پرداخت در محل» (پیش‌فرض طراحی).
- **صفحه‌ها:** فروشگاه، سبد، تسویه، حساب کاربری، شرایط و قوانین — همه انتخاب شده باشند.
- **اجازهٔ ثبت‌نام در تسویه:** اگر می‌خواهی خرید مهمان ساده باشد، «فعال‌سازی ثبت‌نام در صفحهٔ تسویه» را روشن بگذار.

## ۱۱. بازگردانی (Rollback) در چهار سناریو

1. **قالب دردسر شد:** پوستهٔ پیش‌فرض را فعال کن.
   ```bash
   wp theme activate twentytwentyfour
   ```
   یا با FTP نام پوشهٔ `themes/partyab` را به `themes/partyab_off` تغییر بده.
2. **افزونه دردسر شد:** با پیشخوان غیرفعالش کن؛ اگر پیشخوان بالا نمی‌آید:
   ```bash
   mv wp-content/plugins/partyab-fitment wp-content/plugins/partyab-fitment_off
   ```
   داده‌ها در دیتابیس می‌مانند (غیرفعال‌سازی چیزی را حذف نمی‌کند).
3. **خطای ۵۰۰ و دسترسی به پیشخوان نیست:** وردپرس را در حالت بازیابی ببر:
   ```bash
   wp config set WP_ENVIRONMENT_TYPE recovery
   ```
   یا فایل `wp-content/plugins/partyab-fitment` را موقتاً تغییر نام بده.
4. **داده خراب شد:** بکاپ دیتابیس را برگردان (بکاپی که در گام صفر گرفته‌ای).

قبل از هر تغییر بزرگ: **اکسپورت CSV سازگاری** + بکاپ دیتابیس. این دو با هم، بازگشت را بی‌درد می‌کند.

## ۱۲. کارهایی که نکن

- ⛔ حذف (Uninstall) افزونه بدون اکسپورت CSV — جدول سازگاری drop می‌شود.
- ⛔ ویرایش مستقیم فایل‌های قالب با ویرایشگر پیشخوان (یک تایپو = صفحهٔ سفید). برای تغییر ظاهر از «افزودن CSS سفارشی» یا قالب فرزند استفاده کن.
- ⛔ تغییر اسلاگ برگهٔ «گاراژ» به چیز دیگری بدون به‌روزرسانی لینک‌ها (الگو با نام برگه کار می‌کند، ولی لینک‌های منو باید اصلاح شوند).
- ⛔ حذف یا تغییر نام صفحه‌های ووکامرس (سبد، تسویه، حساب کاربری).
- ⛔ نصب روی سایت در حال فروش، در ساعت اوج، بدون بکاپ.

## ۱۳. به‌روزرسانی نسخه‌های بعدی

```bash
# گرفتن نسخهٔ تازه از گیت‌هاب و ساختن زیپ‌ها
git pull
bash bin/build-zips.sh

# نصب روی سایت
wp theme install dist/partyab.zip --force --activate
wp plugin install dist/partyab-fitment.zip --force --activate
```

سپس چک‌لیست بخش ۹ (دست‌کم موردهای ۱، ۵، ۸، ۱۳) را دوباره اجرا کن.
