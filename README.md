# PartYab — پارت‌یاب

نمونهٔ قابل‌کلیک (High-fidelity UI prototype) برای فروشگاه قطعات خودرو **پارت‌یاب**؛
قالب راست‌چین ووکامرس + افزونهٔ سازگاری قطعه و خودرو.

> **دو خروجی دارد:** (۱) نمونهٔ قابل‌کلیک HTML/CSS/JS بدون بیلد،
> (۲) نسخهٔ واقعی وردپرس + ووکامرس: قالب `theme/partyab` و افزونهٔ `plugin/partyab-fitment`.
> داده‌های نمونه (۱۳ محصول، ۱۰ سازنده، ۳۳ مدل) فقط برای دمو هستند؛ قیمت‌ها واقعی نیستند.

## اجرا

```bash
python3 -m http.server 3000 --bind 0.0.0.0
# سپس: http://localhost:3000
```

## هویت v3 — «پاسپورت خودرو» + «ریل سازگاری» + «کاتالوگ فنی»

- **پاسپورت خودرو**: خودروی فعال از یک دراپ‌داون به یک نوار سرمه‌ای زیر هدر تبدیل شده؛ شامل پلاک، مدل/سال/تیپ،
  نوار پوشش کاتالوگ (چند از ۱۳ قطعه) و دکمهٔ تغییر. حالت خالی = پلاک خالی با خط‌چین کهربایی.
- **ریل سازگاری**: بج‌های رنگی روی عکس حذف شدند؛ وضعیت با یک نوار ۳ پیکسلی در لبهٔ کارت (پیوسته/خط‌چین/نقطه‌چین)
  به‌همراه یک خط متن دقیق («سازگار با ۲۰۶ ۱۳۹۹»، «سازگار با شرط · فقط تیپ ۵ و ۶…») نمایش داده می‌شود.
- **کاتالوگ فنی**: فونت مونو (IBM Plex Mono) فقط برای کدهای لاتین، کد OEM روی تصویر، جدول کد فنی،
  رنگ‌بندی معنادار (کهربایی = خودرو/سازگاری، سرمه‌ای = خرید)، شعاع‌های کوچک‌تر و خطوط ۱px به‌جای سایه.
- **نقشهٔ خودرو**: هیرو یک خط‌نگارهٔ SVG از خودروی ایرانی با هات‌اسپات دسته‌ها دارد که فروشگاه را فیلتر می‌کند.
- **ایندکس دسته‌ها** به‌جای کارت‌های تکراری: ردیف‌های فهرست‌گونه با شمارهٔ مونو و نقطه‌چین راهنما.
- **سبد خرید با گاردریل سازگاری**: کشوی سبد آیتم‌محور است (تعداد، حذف، جمع)، هر ردیف همان ریل وضعیت را دارد،
  و اگر قطعه‌ای ناسازگار باشد دکمهٔ «ادامهٔ سفارش» تا تأیید صریح کاربر («با وجود ناسازگاری ادامه می‌دهم») بسته می‌ماند.
  قطعات «ثبت‌نشده» دکمهٔ «درخواست بررسی» می‌گیرند و ردیف‌های بدون خودرو، پیام انتخاب خودرو.
- **گاراژ من**: هر خودرو یک کارت پاسپورت دارد (سازنده، تیپ موتور، پوشش کاتالوگ با نوار پیشرفت، فعال/ذخیره‌شده)،
  به‌همراه «قطعات مناسب خودروی فعال»، چک‌لیست سرویس دوره‌ای قابل تیک‌زدن (ذخیره در `py_service_v1`) و آخرین سفارش‌ها (`py_orders_v1`).
  گاراژ خالی، مدل‌های پرجست‌وجوی ایرانی را به‌صورت چیپ پیشنهاد می‌دهد.
- **تسویه تا تأیید سفارش**: گیرنده، سه روش ارسال با محاسبهٔ زندهٔ جمع، سه روش پرداخت با «پرداخت در محل» به‌عنوان پیشنهاد،
  و صفحهٔ پایان با کد پیگیری، تاریخ تحویل شمسی، خلاصهٔ آیتم‌ها و یادداشت سازگاری. سبد در `py_cart_v2` (مهاجرت از `py_cart_v1`).

### ظاهر هیرو: کارت محصول به‌جای نقشهٔ خودرو

پنل سمت چپ هیرو حالا یک **پیش‌نمایش واقعی کارت محصول** است (کد فنی، برند، کدهای معادل، وضعیت «سازگار با شرط» و قیمت) به‌همراه سه شمارندهٔ کاتالوگ. نقشهٔ خودروی SVG حذف شد.

سه حالت، با یک تنظیم (Customizer یا کد):

```php
set_theme_mod( 'partyab_hero_visual', 'demo' );  // پیش‌فرض: کارت محصول
set_theme_mod( 'partyab_hero_visual', 'photo' ); // عکس قطعات (نسخهٔ قبل از v3)
set_theme_mod( 'partyab_hero_visual', 'none' );  // بدون تصویر، یک ستون متن
```

### نصب خودکار (یک فرمان / یک دکمه)

بعد از فعال‌سازی قالب و افزونه، دیگر لازم نیست کاری دستی بکنید:

```bash
# روی سرور، از ریشهٔ همین مخزن
bash bin/install.sh --path=/var/www/html

# یا مستقیم با WP-CLI
wp partyab install                 # واحد پول ریال
wp partyab install --currency=IRT
wp partyab install --no-images     # بدون تصاویر نمونه
wp partyab install --force         # به‌روزرسانی محصولات موجود با همان SKU
```

یا از پیشخوان: **ابزارها → نصب سریع پارت‌یاب → اجرای نصب خودکار**.

چه کارهایی انجام می‌دهد: بررسی پیش‌نیازها (وردپرس/PHP/mbstring/ووکامرس) → فعال‌سازی قالب →
نام و منطقهٔ زمانی تهران → پیوند یکتا → واحد پول/کشور/ارسال (پیک، پست، حضوری)/پرداخت در محل →
۸ دستهٔ فروشگاه با آیکون → ۱۳ محصول نمونه → تصاویر دمو → ۳۶ ردیف سازگاری → صفحهٔ گاراژ با الگو →
صفحهٔ اصلی و برگهٔ راهنما → تبدیل سبد/تسویه به شورت‌کد کلاسیک → ۴ منو و جایگاه‌ها →
گزارش نهایی با هشدار کش صفحه و شمارش محصولات/سازگاری.

اجرای دوباره بی‌خطر است (idempotent) و محصولات موجود را بازنویسی نمی‌کند مگر `--force`.

### بستهٔ نصب آماده (`dist/`)

دو فایل زیپ آمادهٔ آپلود در پیشخوان وردپرس:

| فایل | آپلود از | نتیجه |
|---|---|---|
| `dist/partyab.zip` (۱٫۱ مگابایت) | نمایش → پوسته‌ها → افزودن پوسته → بارگذاری پوسته | قالب `partyab` |
| `dist/partyab-fitment.zip` (۲۶ کیلوبایت) | افزونه‌ها → افزودن افزونه → بارگذاری افزونه | افزونهٔ سازگاری |

ساخت مجدد پس از هر تغییر:

```bash
bash bin/build-zips.sh
```

اسکریپت، پوشهٔ `partyab` و `partyab-fitment` را در ریشهٔ زیپ می‌گذارد (همان ساختاری که وردپرس می‌خواهد)
و فایل‌های سیستم‌عامل/مخفی را حذف می‌کند. بدون هیچ ابزار بیلد، `node_modules` یا وابستگی خارجی.

### نصب در ۶ گام

1. **پیش‌نیاز:** وردپرس ۶.۴+، PHP 7.4+، ووکامرس فعال، پیوندهای یکتا روی «نام نوشته».
2. **قالب:** پوشهٔ `theme/partyab` را در `wp-content/themes/partyab` بگذارید (یا zip بسازید و از پیشخوان نصب کنید)، سپس «نمایش → پوسته‌ها → پارت‌یاب → فعال‌سازی».
3. **افزونه:** پوشهٔ `plugin/partyab-fitment` را در `wp-content/plugins/partyab-fitment` بگذارید و از «افزونه‌ها» فعال کنید. افزونه در فعال‌سازی جدول `{prefix}partyab_fitment` را می‌سازد و خودرو را در کوکی `partyab_vehicle` نگه می‌دارد.
4. **داده (ترتیب مهم):** اول «محصولات → درون‌ریزی» و `sample/products.csv` (شامل متای `_partyab_oem`، `_partyab_brand`، `_partyab_equivalents`)، **بعد** «ابزارها → سازگاری پارت‌یاب» و ایمپورت `sample/fitment.csv` — ایمپورتر سازگاری ردیف‌ها را با SKU به محصولات موجود وصل می‌کند.
5. **صفحه‌ها:** برگهٔ «گاراژ» را بسازید و الگوی «گاراژ پارت‌یاب» را برایش انتخاب کنید؛ در «تنظیمات → خواندن» صفحهٔ اصلی را یک برگهٔ خالی با الگوی پیش‌فرض بگذارید تا `front-page.php` اجرا شود.
6. **منوها:** «نمایش → فهرست‌ها» — منوی اصلی، منوی دسته‌های فوتر و منوی راهنمای فوتر.

### رفتار سازگاری در وردپرس

- خودروی فعال در کوکی `partyab_vehicle` (JSON: `make_id`, `model_id`, `year`, `engine`) — سمت سرور معتبرسازی می‌شود؛
  انتخاب‌گر خودرو در `assets/js/partyab.js` از REST `partyab/v1` می‌خواند و کارت‌ها بدون JavaScript هم وضعیت درست را دارند.
- پنج حالت: «سازگار»، «سازگار با شرط»، «ناسازگار»، «ثبت‌نشده»، «عمومی» — هر حالت با متن + آیکون + ریل رنگی، نه فقط رنگ.
- فیلتر «فقط سازگار با …» در آرشیو با `?compat=1` و `pre_get_posts` سمت سرور اعمال می‌شود (بدون جاوااسکریپت هم کار می‌کند).
- سبد خرید و تسویه، سبد و تسویهٔ واقعی ووکامرس است؛ شمارندهٔ هدر با fragmentهای ووکامرس به‌روز می‌شود.
- بدون هیچ درخواست خارجی: فونت‌ها، تصاویر و آیکون‌ها همه محلی هستند.

راهنمای گام‌به‌گام و کامل‌تر (محیط تست، معماری، امنیت، عیب‌یابی): [`docs/wordpress-guide.md`](docs/wordpress-guide.md)

## نکات طراحی

- **رنگ‌ها:** سرمه‌ای `#132238`، کهربایی `#F59E0B`، پس‌زمینه `#F7F9FC` (کهربایی فقط برای خودرو و سازگاری)

- **پالت جست‌وجوی سریع ⌘K** و ناوبری پایین صفحه در موبایل
- کدهای فنی معادل با کپی، کیت «همراه این قطعه» با ۵٪ تخفیف، فرم استعلام سازگاری/قطعه، تضمین بازگشت ۷ روزه
- بریک‌پوینت‌ها: ۱۱۸۰ / ۱۰۲۴ / ۸۶۰ / ۶۴۰ / ۳۸۰ پیکسل
- همهٔ وضعیت‌ها با **متن + آیکون** مشخص می‌شوند، نه فقط رنگ

## قدم بعدی (تولید)

1. جایگزینی داده‌های نمونه با کاتالوگ واقعی: `plugin/partyab-fitment/data/vehicles.json` را از منبع رسمی خودروسازان/سازندگان قطعه پر کنید.
2. ورود دسته‌ای سازگاری از فایل تأمین‌کننده‌ها به CSV با همان ستون‌های `sample/fitment.csv`.
3. اتصال فرم «استعلام سازگاری» به ایمیل/CRM و ثبت رویدادهای انتخاب خودرو برای سنجش نرخ تبدیل.
4. تست پرداخت واقعی (درگاه بانکی ایرانی) و قالب‌های ایمیلی ووکامرس با فونت فارسی.
